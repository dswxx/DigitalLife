# 系统设计

系统围绕两种交流方式：普通 AI 的一问多答，以及与带有人格的数字人持续交谈。
后端使用 FastAPI 和 httpx，前端使用 Vue 3、TypeScript 和 Pinia；数据使用 JSON 与 JSONL 文件。

## 请求链路

1. 页面发送会话 ID 和当前问题。
2. 后端保存问题，给每位参与者并发发起模型请求。
3. 上下文函数将人格、历史原文、当前问题组装成消息。
4. 协议适配器转为 OpenAI 兼容或 Anthropic Messages 请求，解析 SSE 响应。
5. 通过 NDJSON 向页面逐段推送正文、思考和状态；每位完成后立即保存回答。

普通 AI 不发送人格，只使用当前会话的个人问答。数字人发送所选人格，使用自己的跨会话历史。
人格原文直接作为 system；不会附加时间提示、自动摘要、记忆目录或检索材料。
历史仅使用真实用户消息和本人的回答，同轮其他人的观点不会进入请求。

模型窗口是有限的。请求预留输出额度与安全余量，再从最近原文向前取历史。
当前问题保持完整，不能装入窗口时直接报错。原文不会因请求裁剪而改动。

## 存储

| 位置 | 内容 |
| --- | --- |
| `settings.json` | 平台、真实密钥、模型窗口及输出额度 |
| `templates/<id>.json` | 可复用的人格蓝图 |
| `sessions/<id>/info.json` | 标题、当前提问对象、时间和轮数 |
| `sessions/<id>/messages.jsonl` | 本会话所有问题、各人的回答、错误和历史参与者 |
| `humans/<id>/identity.json` | 实体身份、平台、模型与人格绑定 |
| `humans/<id>/history.jsonl` | 从创建起累积的一份个人历史，用 sessionId 标记来源 |
| `.trash/` | 已删除实体的原文件 |

会话文件和实体历史分别保存，数据冗余是明确选择。问题写入收到它的每位实体，回答仅写入回答者的历史。
一位实体没有分会话历史文件。删除会话不删除实体历史；删除实体不影响会话中已保存的回答。
轮次和消息使用稳定 ID，不通过时间戳猜测问题与回答的对应关系。

JSON 用临时文件替换保存，JSONL 追加后刷盘。两处记录不是跨文件事务：写入失败会报错，不自动补写或修复。
读取损坏记录会明确报错，保留原文件供检查与恢复。

## 运行时

应用启动读取设置、人格、身份和会话概况，不扫描所有聊天原文。
打开会话时读取它的记录，之后复用；实体历史在首次需要上下文时读取，后续追加同步到内存列表。
服务重启后从磁盘重新加载，不另建缓存文件或索引服务。

同一会话一轮结束后才能再次提问或修改参与者；不同会话可并发。
同一实体的记录追加使用锁；跨会话交错完成时按 roundId 配对上下文，未完成的其他轮次暂不携带。
浏览器停止接收不会中断已经开始的后台回答；后台继续保存，完成前会话仍保持忙碌。

## 模块职责

- `main.py`：HTTP、访问控制与前端托管。
- `runtime.py`：启动数据、按需加载、记录保存与运行期间的状态。
- `chat.py`：并发调用、流事件和回答保存。
- `context.py`：人格、历史原文和当前问题的组装。
- `life.py` / `sessions.py`：身份、个人历史和会话文件。
- `settings.py` / `templates.py` / `presets.py`：配置与人格。
- `store.py`：文件读写与进程内锁。
- `adapters/`：两种模型协议与 HTTP 传输。

后续功能先用普通函数实现，在需要的请求入口调用；有明确需求后再引入额外存储和调度机制。
