# 系统设计

系统围绕两种交流方式：普通 AI 的一问多答，以及与带有人格的数字人持续交谈。
后端使用 FastAPI 和 httpx，前端使用 Vue 3、TypeScript 和 Pinia；数据使用 JSON 与 JSONL 文件。

## 请求链路

1. 页面发送会话 ID 和当前问题。
2. 后端保存问题，给每位参与者并发发起模型请求。
3. 完整组装人格、已有摘要、未覆盖的历史正文和当前问题，不估算窗口或提前裁剪。
4. 协议适配器转为 OpenAI 兼容或 Anthropic Messages 请求，解析 SSE 响应。
5. 通过 NDJSON 向页面逐段推送正文、思考和状态；每位完成后立即保存回答。

普通 AI 不发送人格，只使用当前会话的个人问答。数字人发送所选人格，使用自己的跨会话历史。
人格原文和可选的历史摘要放在 system。普通 AI 省略人格，发生压缩后也可携带自己本会话的摘要。
历史仅使用真实用户消息和本人的回答正文，reasoning 留在归档与页面，不进入正式请求或摘要请求。
同轮其他人的观点不会进入请求。

模型窗口由服务商实际限制决定。应用不设置输入预算，不使用默认 128k、百分比阈值或 token 估算截断历史。
max_tokens 仅控制生成长度，继续支持输出参数兼容；旧配置 contextWindow 不再参与请求。

## 自动上下文压缩

职责分为三处：context.build_context 纯组装；协议层将明确的输入超限归类为 AdapterError(kind="context_limit")；
compression.stream_answer 包裹正式调用，处理压缩与重试，chat 继续负责并发、转发与保存。

```text
完整组装 → 调用模型 → 成功则直接转发
                  → 明确超限且尚未输出 → 压缩历史 → 重新组装、重试
                  → 其他错误或已经输出 → 报告错误、保存实际收到的内容
```

识别同时覆盖 HTTP 错误和 SSE 流内错误，优先服务商 code/type，再识别明确文案。
不能仅凭 400/413、token 或 length 关键词触发。总上下文超限先于 max_tokens 参数兼容处理，避免两条重试路径混淆。
输出范围、配额、鉴权、超时和普通请求体过大不触发压缩；不认识的错误保留平台信息直接报告。

超限后将较早历史与已有摘要一起总结，优先保留最近两轮；仍超限时允许把最近两轮也纳入压缩，最后可进一步缩短已有摘要。
人格和当前问题始终完整保留。没有历史可压缩时明确提示缩短输入或更换模型。
摘要也被平台判定超限时才把资料二分，按原始顺序逐批整合前一批摘要；允许拆分特别长的单条消息。
字符长度只用于二分位置与拒绝未缩短的结果，不作为 token 预算。每次正式请求最多压缩重试 3 次，每次整理最多尝试 32 次摘要调用，避免无限循环。

只有所有批次成功、摘要正常结束且确实缩短，才原子替换摘要状态。
空摘要、截断摘要、分批中途失败或保存失败都会报告错误；未提交半份摘要，完整原文保持不变。
失败仅影响当前参与者，其他参与者继续回答。已提交的完整摘要可在后续请求继续复用。

每个实体的 context.json 按作用域存储 summary、throughRoundId、updatedAt 和 model。
数字人使用 life，普通 AI 使用 session:<id>；摘要不是聊天原文，不追加进 history.jsonl。
后续请求仅携带已有摘要和未覆盖原文，服务重启后继续复用。删掉派生摘要文件可从完整原文重新生成。

同一实体的摘要读改写串行；正式回答不持摘要锁，摘要网络等待不占实体历史读写锁。
同时超限时，后到者发现摘要已更新就直接复用，不重复整理。
覆盖轮次只推进到不可再追加的历史前缀，不越过仍在其他会话作答的轮次，避免遗漏稍后完成的回答。
无法推进安全前缀时明确报错，等待其他会话完成后再试，不悄悄丢弃原文。

到达真实边界时会先经历一次失败请求，再等待压缩与重试。用量以平台返回为准；项目内 token 估算器仅用于缺失用量时的展示。

## 存储

| 位置 | 内容 |
| --- | --- |
| `settings.json` | 平台、真实密钥及输出额度 |
| `templates/<id>.json` | 可复用的人格蓝图 |
| `sessions/<id>/info.json` | 标题、当前提问对象、时间和轮数 |
| `sessions/<id>/messages.jsonl` | 本会话所有问题、各人的回答、错误和历史参与者 |
| `humans/<id>/identity.json` | 实体身份、平台、模型与人格绑定 |
| `humans/<id>/history.jsonl` | 从创建起累积的一份个人历史，用 sessionId 标记来源 |
| `humans/<id>/context.json` | 可选摘要状态，按实体或普通 AI 会话隔离，覆盖位置以 roundId 标记 |
| `.trash/` | 已删除实体的原文件 |

会话文件和实体历史分别保存，数据冗余是明确选择。问题写入收到它的每位实体，回答仅写入回答者的历史。
一位实体没有分会话历史文件。删除会话不删除实体历史；删除实体不影响会话中已保存的回答。
轮次和消息使用稳定 ID，不通过时间戳猜测问题与回答的对应关系。

JSON 用临时文件替换保存，JSONL 追加后刷盘。两处记录不是跨文件事务：写入失败会报错，不自动补写或修复。
读取损坏记录会明确报错，保留原文件供检查与恢复。

## 运行时

应用启动读取设置、人格、身份和会话概况，不扫描所有聊天原文。
打开会话时读取它的记录，之后复用；实体历史在首次需要上下文时读取，后续追加同步到内存列表。
服务重启后从磁盘重新加载；摘要文件按需读取，聊天原文的内存列表不额外持久化为缓存文件。

同一会话一轮结束后才能再次提问或修改参与者；不同会话可并发。
同一实体的记录追加使用锁；跨会话交错完成时按 roundId 配对上下文，未完成的其他轮次暂不携带。
浏览器停止接收不会中断已经开始的后台回答；后台继续保存，完成前会话仍保持忙碌。

## 模块职责

- `main.py`：HTTP、访问控制与前端托管。
- `runtime.py`：启动数据、按需加载、记录保存与运行期间的状态。
- `chat.py`：并发调用、流事件和回答保存。
- `context.py`：人格、可选摘要、历史原文和当前问题的组装。
- `compression.py`：超限调用保护、二分摘要、有限重试与覆盖位置管理。
- `life.py` / `sessions.py`：身份、个人历史和会话文件。
- `settings.py` / `templates.py` / `presets.py`：配置与人格。
- `store.py`：文件读写与进程内锁。
- `adapters/`：两种模型协议与 HTTP 传输。

后续功能先用普通函数实现，在需要的请求入口调用；有明确需求后再引入额外存储和调度机制。
