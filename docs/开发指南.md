# 开发指南

安装与启动见 [README](../README.md)，数据与请求链路见 [系统设计](系统设计.md)。

## 代码阅读路线

代码中的 `【核心】` 标记用于定位主流程与容易误改的约束。模块说明交代职责，
函数注释解释输入、结果和副作用；行内注释集中解释并发、消息边界与保存顺序。

建议按以下顺序阅读：

| 阶段 | 入口 | 重点 |
| --- | --- | --- |
| 启动与状态 | `run.py` → `server/runtime.py` | 先加载概况，原文按需加载并复用 |
| 页面提问 | `web/src/store.ts` 的 sendQuestion | 建立轮次快照，绑定事件到固定回答对象 |
| HTTP 流 | `server/main.py` 的 ask | 一次请求携带多个模型的 NDJSON 事件 |
| 并发调用 | `server/chat.py` 的 ask / _run_parallel / _run_seat | 会话锁、每人一个线程、队列收尾和错误隔离 |
| 上下文 | `server/context.py` 的 build_context / ordered_history | 完整组装正文、排除思考、轮次配对 |
| 超限保护 | `server/compression.py` 的 stream_answer | 先请求、明确超限再压缩、二分摘要与有限重试 |
| 模型协议 | `server/adapters/__init__.py` → `server/adapters/sse.py` | SSE 分块、字段映射、超时和输出额度兼容 |
| 记录保存 | `server/runtime.py` 的 write_message → `server/store.py` | 会话与个人历史两处保存，先保存后报告完成 |
| 页面接收 | `web/src/api.ts` 的 ask → `web/src/store.ts` 的 applyEvent | UTF-8 与 JSON 行缓冲，按 seatNo 更新卡片 |

可以用 `rg -n '【核心】' server web/src` 直接查找重点。
新增注释时说明设计原因和实际边界，避免逐行复述代码或描述尚未实现的能力。

## 本地开发

```powershell
py -3 -m pip install -r requirements-dev.txt
py -3 run.py --reload
```

修改前端后，在 `web/` 下执行 `npm run typecheck` 和 `npm run build`；后端托管 `web/dist/`，并在入口页面注入访问令牌。

## 测试

```powershell
py -3 scripts/check.py --unit
py -3 scripts/check.py
py -3 scripts/check.py --ui
```

浏览器测试可以用 `--ui --cdp-port 9333` 连接已开启调试端口的浏览器，也可自行启动 Chrome 或 Edge。
所有测试数据由 `tests/support.py` 合成，在 `tests/.tmp-*/` 下运行并清理；没有旧项目或个人档案依赖。
HTTP 和浏览器测试调用 `tests/mock_upstream.py` 的本机假上游，不使用真实平台。

| 测试 | 验证内容 |
| --- | --- |
| `test_core.py` | 上下文、懒加载、两处保存、故障、历史分页与并发 |
| `test_adapters.py` | OpenAI、Anthropic、UTF-8 流、上游错误和额度兼容 |
| `test_compression.py` | 真实超限触发、二分摘要、重试边界、原文保留、失败和并发隔离 |
| `test_http.py` | 真实 HTTP 流、并发、访问令牌、密钥掩码和基本管理操作 |
| `test_ui.py` | 导航、选人、流式问答、历史重载、会话隔离和输出转义 |
| `test_docs.py` | 文档链接、版本与 Windows 启动器 |

## 接口

接口需要 `x-digitallife-token`；启动令牌由后端注入入口 HTML。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health`、`/api/bootstrap` | 运行状态与页面启动数据 |
| POST | `/api/settings` | 保存平台配置 |
| POST | `/api/providers/{id}/models`、`/api/providers/{id}/test` | 模型列表与连接测试 |
| GET / POST | `/api/templates`、`/api/lives`、`/api/sessions` | 列表与创建 |
| PATCH / DELETE | `/api/templates/{id}`、`/api/sessions/{id}` | 修改与删除 |
| DELETE | `/api/lives/{id}` | 将实体移入回收目录 |
| GET | `/api/sessions/{id}/messages?limit=3&before=<roundId>` | 按轮次分页读取原文 |
| POST | `/api/ask` | 一问多答，接收 sessionId 和 question |

聊天返回 NDJSON，一行一个事件。轮次事件为 round_start / round_done，参与者事件携带 seatNo。
正文、推理、提示分别使用 text / reasoning / notice；保存完成后发出 seat_done，错误使用 error。

## 配置与修改

`settings.json` 中 advanced.maxTokens 控制单次输出上限，modelInfo 可按模型保存 maxOutput。
不再计算输入预算，旧 advanced.contextWindow 和 modelInfo 中的 contextWindow 不再生效。
平台拒绝输出额度时，适配器会按平台限制重试并显示提示；上下文超限单独分类，交给压缩保护层。
连续无输出超时使用环境变量 DL_IDLE_MS，默认 90000 毫秒。

压缩参数集中在 `server/compression.py`：KEEP_RECENT_ROUNDS=2、MAX_SUMMARY_TOKENS=2048、MAX_COMPRESSION_RETRIES=3、MAX_SUMMARY_CALLS=32。
最近轮数是保留原文的偏好，摘要输出长度和调用次数用于限制生成与重试，不构成输入窗口预算。
压缩与正式回答使用同一参与者的模型；摘要失败会明确报错，不退回未完整生成的摘要。
context.json 是可选派生文件，不需要转换已有原文或升级数据格式。

人格与平台预设在 `server/presets.json`；请求组装入口是 `server/context.py`。
增加协议时在 `server/adapters/` 实现请求和事件映射，并注册到统一入口。
增加上下文来源时先增加普通函数，在组装位置直接调用，不预先建设插件、任务或记忆框架。

修改真实数据前停服并完整备份 `data/`。备份保存在 `.backups/`，与运行目录分开。
当前代码仅维护当前数据格式，不附带旧版本导入与迁移工具。
