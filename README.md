# 数字生命 DigitalLife

> **一群各自活着的数字生命。**
> 你读过的作者、敬重的人、想请教的角色——把他们的思维方式做成蓝图，
> 让每个个体带上自己的记忆活着，然后坐下来听他们怎么说。

本地运行，数据全在你自己机器上（`data/`，纯 JSON / JSONL / Markdown）。

**名字分两层**（免得以后看着别扭）：

- **数字生命**是这个产品：人格蓝图、活着的个体、他们的记忆与一生
- **圆桌对话**是其中一个功能：让几位数字人坐在一起，同时或轮流回答你的问题

---

## 怎么跑

需要 **Python ≥ 3.11**（这台机器上 `python` 是 3.9，**一律用 `py -3`**）和 Node ≥ 20。

```bash
py -3 -m pip install -r requirements.txt      # 后端依赖，只有三个
cd web && npm install && npm run build && cd ..   # 前端构建一次
py -3 run.py                                   # 或双击 启动数字生命.cmd
```

打开它打印的 `http://127.0.0.1:8787`。第一次启动会自动播种 7 份内置人格模板。
只监听本机，外网访问不到；关掉窗口就是停服务。

**还没构建前端时**打开只会看到一张提示页，启动信息里会告诉你差哪两步。

## 它和普通"多模型聊天"有什么不同

**一、人格是蓝图，活着的是个体。**
「苏格拉底」是一份人格（写一次），你可以在 DeepSeek 上建一个他、在 Kimi 上再建一个他。
两个人格相同、经历不同——就像同一个人的两次人生。所以库分成两半：
上面是模板（不绑厂商、没有记忆），下面是各平台上活着的个体。

**二、记忆属于个体，不属于对话。**
你和他在某张桌子上聊过的话，写进**他自己**的记录里，不跟桌子绑定。
删掉那张桌子，他的记忆还在；删掉他，别处也不会缺一块。
聊得久了，他会自己把旧的部分压成摘要、把值得长期记住的事挑出来——
**这件事在两轮之间的后台发生，你看不到他在整理**。

**三、记忆是人能读能改的东西。**
长期记忆是一条一个 Markdown 文件（YAML 头 + 正文），目录只放一行摘要。
他记错了，你在界面上删掉那一条就行。这是"他真当成一段生命"的关键——
记忆不是埋在向量库里的黑箱。

**四、裸模型是对打探针。**
有一种模板是"纯基线"：请求里**一个 `system` 字段都不发**——不是发空串，是压根不构造。
把它和某位数字人放同一张桌子上，你就能看出"差异里有多少来自人格提示词"。
（代价是它不积累记忆，它本来也不是用来陪伴的。）

**五、桌子有两种规矩。**
- **并排**：所有人同时听到同一句问题，互相听不到这一轮的回答——真的并发，字是交错来的
- **会议**：按座位顺序一个一个说，后面的人听得到前面的人（前面的原话会进他的这次请求）

## 接口一览

除 `/` 之外都要带 `x-digitallife-token`（服务端注入到 HTML 里，每次启动随机生成）。

```
GET    /api/health                            版本、接口版本、数据版本
GET    /api/bootstrap                         启动要的一切（设置+模板+生命+桌子）
GET    /api/settings                          平台/高级设置（**密钥只回掩码**）
POST   /api/settings                          保存（没传的字段一律不动）
POST   /api/providers/{id}/models             拉这家有哪些模型
POST   /api/providers/{id}/test               连通性测试

GET    /api/templates            POST         人格蓝图
PATCH  /api/templates/{id}       DELETE       （改内容会改 id，用着它的生命自动跟着走）

GET    /api/lives                POST         数字人（个体）
GET    /api/lives/{id}           PATCH  DELETE
GET    /api/lives/{id}/memory    POST         长期记忆
PATCH  /api/lives/{id}/memory/{mid}  DELETE
GET    /api/lives/{id}/sessions/{sid}         他在那次会话里的亲历（?tail=1 只要未压缩的）
GET    /api/lives/{id}/timeline               「一生」：按天聚合
POST   /api/lives/{id}/sessions/{sid}/compact 手动整理（平时它在后台自己整理）

GET    /api/sessions             POST         桌子
PATCH  /api/sessions/{id}        DELETE
POST   /api/ask                               **流式对话**（NDJSON，一行一个事件）
```

`/api/ask` 产出的事件：`seat_start` / `text` / `reasoning` / `notice` / `limit` /
`seat_done` / `error` / `round_done`。每块都带 `seatNo`——并排模式下多个席位是同时跑的。

## 数据长什么样

```
data/
├── settings.json               平台 / 密钥 / 高级设置 / 从平台学到的模型上限
├── templates/<模板>.json       人格蓝图
├── sessions/<会话>.json        桌子：有谁、并排还是会议
└── humans/<生命>/
    ├── identity.json           来自哪个蓝图、绑哪家 API、什么时候出生
    ├── memory/                 长期记忆：目录 + 一条一个 Markdown
    └── sessions/               他亲历的记录（JSONL）+ 水位线索引
```

两个格式是**有意区分**的：

| 文件 | 格式 | 为什么 |
|---|---|---|
| 对话记录 | JSONL，只追加 | 机器日志：能 grep、能 `tail -f`、崩了不丢前面的 |
| 长期记忆 | Markdown + YAML 头 | 人要读要改的：**他记错了你能直接删掉那一条** |
| 桌子 / 水位线 | 小 JSON，原子替换 | 每次请求都要读，所以必须小；原文永远不删 |

**原文是真相，摘要和记忆都是可以重算的派生物。** 压缩从来不删原文，只把水位线往前推一格；
请求路径只读水位线之后的尾巴，更老的原文归档在磁盘上根本不解析——所以生命活得越久，
不会越慢。完整的字段含义见 [`开发指南.md`](开发指南.md)。

## 四条底线

1. **JSON 一律 `ensure_ascii=False`** —— 否则「苏格拉底」会变成 `\u82cf…`，记事本就看不懂了。
   "数据是你的"全靠这一个参数
2. **密钥永不出本机**：只存 `data/settings.json`，接口只回掩码；掩码原样回传不会覆盖真密钥
3. **纯基线的请求里一个 `system` 字段都不发** —— 不是发空串，是压根不构造
4. **请求路径永远不调用模型做压缩** —— 压缩在两轮之间的后台跑；裁剪是保底，永不失败
